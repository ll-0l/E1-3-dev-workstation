# Mini NPU Simulator 초보자 가이드

이 문서는 프로젝트를 처음 접한 사람이 **실행 → 계산 → 판정** 순서로 이해할 수 있게 만든 5분 안내서예요.

> 상세한 구현 근거는 [README](../README.md), 평가 항목별 근거는 [동료평가 대응표](PEER_REVIEW.md)에서 확인할 수 있어요.

## 30초 요약

```text
숫자 패턴 입력
  → Cross 필터와 MAC 계산
  → X 필터와 MAC 계산
  → 두 점수 비교
  → Cross / X / UNDECIDED 출력
```

| 핵심 질문 | 답 |
|---|---|
| 무엇을 판정하나요? | 숫자 패턴이 Cross인지 X인지 판정해요. |
| 어떻게 판정하나요? | 두 필터와의 MAC 점수를 비교해요. |
| 점수가 같으면요? | 억지로 고르지 않고 `UNDECIDED`로 처리해요. |
| 별도 설치가 필요한가요? | 아니요. Python 3.8 이상이면 돼요. |

## 1. 프로그램 이해하기

숫자로 표현된 그림이 십자가(`Cross`)에 가까운지 X에 가까운지 판정하는 프로그램이에요.

먼저 세 가지 용어만 알면 돼요.

- **패턴**: 판정할 숫자 그림
- **필터**: 비교 기준이 되는 십자가 또는 X 모양
- **MAC 점수**: 패턴과 필터가 같은 위치에서 얼마나 많이 겹치는지 나타내는 값

십자가 패턴을 두 필터에 겹치면 다음처럼 계산돼요.

```text
십자가 패턴 × 십자가 필터 = 5점
십자가 패턴 × X 필터      = 1점
→ 십자가 필터의 점수가 더 높으므로 Cross로 판정
```

점수는 절대적인 합격선이 아니에요. 같은 패턴에 대해 **Cross 점수와 X 점수를 비교해 더 높은 쪽**을 선택해요.

## 2. 직접 실행하기

Python 3.8 이상만 있으면 되고, 별도 라이브러리는 필요하지 않아요.

```bash
python3 main.py
```

처음에는 아래 두 모드만 확인하면 충분해요.

| 선택 | 기능 | 처음 볼 때 확인할 것 |
|---:|---|---|
| 1 | 3×3 필터와 패턴을 직접 입력 | 입력 → 점수 → 판정의 전체 흐름 |
| 2 | `data.json`의 여러 패턴을 자동 분석 | PASS/FAIL, 성능표, 결과 요약 |

모드 3~5는 패턴 생성, 저장 방식 비교, 1000×1000 대규모 실험을 위한 보너스 기능이에요.

### 직접 입력해 보기

메뉴에서 `1`을 고르고 아래 행렬을 한 줄씩 입력하세요.

```text
필터 A (십자가)       필터 B (X)          패턴 (X)
0 1 0                 1 0 1                1 0 1
1 1 1                 0 1 0                0 1 0
0 1 0                 1 0 1                1 0 1
```

예상 결과는 다음과 같아요.

```text
A 점수: 1.0
B 점수: 5.0
판정: B
```

B는 X 필터이므로 입력 패턴을 X로 판정한 거예요. 전체 화면은 [실행 로그 1장](RUN_LOG.md#1-모드-1--예시-입력-cross-필터--x-필터--x-패턴)에서 확인할 수 있어요.

## 3. MAC 계산 이해하기

MAC은 **곱하고(Multiply), 누적해서 더한다(Accumulate)** 는 뜻이에요.

```python
total = 0.0
for i in range(n):
    for j in range(n):
        total += pattern[i][j] * filter[i][j]
```

N×N 행렬에는 칸이 N²개 있으므로 계산도 N²번 반복돼요.

- 3×3: 9번 계산
- 5×5: 25번 계산
- 25×25: 625번 계산

따라서 시간 복잡도는 **O(N²)** 이에요. 한 변의 길이가 2배가 되면 계산량은 약 4배가 돼요.

## 4. 결과 읽기

| 결과 | 뜻 |
|---|---|
| `Cross` | Cross 필터 점수가 더 높음 |
| `X` | X 필터 점수가 더 높음 |
| `UNDECIDED` | 두 점수가 사실상 같아 판정할 수 없음 |
| `PASS` | 판정과 `data.json`의 정답이 같음 |
| `FAIL` | 판정과 정답이 다르거나, 동점 또는 데이터 오류가 있음 |

### 왜 `UNDECIDED`가 필요한가요?

컴퓨터는 `0.1` 같은 일부 소수를 정확히 저장하지 못해요. 수학적으로 같은 점수도 아래처럼 조금 다르게 계산될 수 있어요.

```text
0.9
0.8999999999999999
```

이 프로그램은 두 점수의 차이가 `1e-9`보다 작으면 같은 점수로 보고 `UNDECIDED`를 출력해요.

### FAIL 3개는 프로그램 오류인가요?

`data.json` 실행에서 6개 중 3개가 FAIL인 것은 프로그램 오류가 아니에요. 세 케이스 모두 정확히 계산하면 두 필터 점수가 같은 **의도된 동점 데이터**예요. 프로그램은 억지로 정답을 고르지 않고 동점 규칙에 따라 정직하게 FAIL로 집계해요.

## 5. 데이터 처리 흐름

모드 2의 처리 흐름은 다음과 같아요.

```text
data.json 읽기
  → 필터와 패턴의 크기·숫자 검사
  → +, cross, x 표기를 Cross와 X로 통일
  → Cross/X MAC 점수 계산
  → 판정과 정답 비교
  → PASS/FAIL 및 성능 요약 출력
```

잘못된 데이터 하나 때문에 전체 프로그램이 멈추지 않아요. 문제가 있는 케이스만 `스키마`, `동점`, `판정 불일치` 중 하나로 분류하고 다음 케이스를 계속 처리해요.
